الدليل التنفيذي الشامل للانتقال إلى LangGraph

كيف ننقل "كوتش AI" من RAG خطي إلى نظام تعليمي متعدد الوكلاء (Multi-Agent) قابل للتطور والتصحيح الذاتي

📅 بعد إتمام المراحل الست السابقة 🎯 الهدف: Agentic RAG + ذاكرة + تدخل بشري 🛠️ التقنيات: LangGraph.js, Node.js, Supabase/Postgres, SSE

01 لماذا LangGraph الآن؟

لقد أكملت المراحل الست بنجاح: Query Routing، Hybrid Search، Structural Chunking، GraphRAG، Reranking، وGrounded Prompt. هذا يعني أن كل مكون من مكونات الاسترجاع والتوليد أصبح جاهزاً. لكن ما ينقصك هو "المدير" الذي ينسق بين هذه المكونات، ويقرر متى يستخدم كل واحد منها، ويصحح المسار إذا فشل.

LangGraph هو هذا المدير. هو إطار عمل لبناء تطبيقات AI على شكل رسوم بيانية (Graphs)، حيث تكون العقد (Nodes) هي خطوات المعالجة، والحواف (Edges) هي مسارات التنفيذ التي يمكن أن تكون شرطية أو دورية. هذا يسمح للـ AI بالتفكير خطوة بخطوة، والرجوع للخلف، وتجربة مسارات بديلة.

02 المكونات الأساسية لـ LangGraph

المكونالشرحمثال في كوتش AI
State (الحالة) الذاكرة التي تنتقل بين الخطوات. يتم تعريفها باستخدام Annotation.Root مع إمكانية إضافة reducer لتجميع القيم (مثل سجل المحادثة). نص السؤال، الأجزاء المسترجعة، الإجابة النهائية، عدد محاولات إعادة الصياغة، الكلية، السنة الدراسية.
Nodes (العقد) دوال JavaScript تستقبل الحالة وتعيد تحديثاً جزئياً لها. كل عقدة تمثل خطوة أو وكيلاً متخصصاً. عقدة البحث، عقدة التقييم (Grader)، عقدة إعادة الصياغة، عقدة توليد الإجابة.
Edges (الحواف) تحدد الانتقال بين العقد. يمكن أن تكون عادية (دائماً من A إلى B) أو شرطية (تعتمد على الحالة). إذا كان التقييم "جيد" → اذهب للتوليد. إذا كان "سيئ" → اذهب لإعادة الصياغة.
Checkpointer (نقاط الحفظ) يحفظ حالة الرسم البياني بعد كل خطوة في قاعدة بيانات (Postgres/Supabase). يسمح باستئناف المحادثة لاحقاً. الطالب يغلق المتصفح ويعود بعد ساعتين ليكمل نفس المحادثة من حيث توقف.
Human-in-the-Loop (HITL) إمكانية إيقاف التنفيذ عند نقطة معينة (Breakpoint) وطلب تدخل بشري (موافقة، تعديل، إدخال). قبل حذف ملف طالب أو تعديل درجة، يتوقف النظام ويطلب موافقة الأدمن.

03 كيف يندمج LangGraph مع المراحل الست السابقة

لن نبدأ من الصفر. كل تقنية من المراحل الست ستصبح عقدة (Node) أو حافة شرطية (Conditional Edge) داخل رسم LangGraph البياني.

التقنية السابقةدورها في LangGraphالعقدة / الحافة
Query Routing تصبح عقدة البداية (Router) التي تقرأ السؤال وتقرر أي مسار تتبع (بحث في الأدوية، بحث في المناهج، أو إجابة مباشرة). Router Node
Hybrid Search + BM25 تصبح عقدة البحث (Retriever) التي تجلب 20-50 جزءاً من قاعدة البيانات. Search Node
Reranking تصبح عقدة إعادة الترتيب التي تأخذ الأجزاء من البحث وتعيد ترتيبها وتختار أفضل 5. Rerank Node
Grounded Prompt يصبح عقدة التوليد (Generator) التي تصوغ الإجابة النهائية من الأجزاء المختارة، مع تعليمات صارمة بعدم الهلوسة. Generate Node
GraphRAG (Neo4j) يمكن استدعاؤه كأداة إضافية داخل عقدة البحث لاسترجاع العلاقات بين الأدوية والأمراض. Graph Tool
الإضافة الجديدة (Agentic RAG): سنضيف عقدة التقييم (Grader) بين البحث والتوليد. هذه العقدة تقرأ الأجزاء وتقرر: "هل هذه الأجزاء تجيب على السؤال؟" إذا كان الجواب "لا"، ننتقل إلى عقدة إعادة الصياغة (Rewrite) ونعيد البحث. هذا هو جوهر التصحيح الذاتي (Self-Correction)[reference:0].

04 المراحل التنفيذية للانتقال إلى LangGraph

المرحلة 0: التأسيس والاعتماديات

قبل كتابة أي كود، نحتاج إلى تثبيت المكتبات الأساسية وإعداد قاعدة البيانات لحفظ الحالات (Checkpointing).

# تثبيت LangGraph والاعتماديات npm install @langchain/langgraph @langchain/core @langchain/langgraph-checkpoint-postgres # (اختياري) تثبيت مكتبة المشرف الجاهزة npm install @langchain/langgraph-supervisor

إعداد قاعدة البيانات (Checkpointer): سنستخدم Postgres (Supabase). نحتاج إلى إنشاء الجداول اللازمة. الحزمة @langchain/langgraph-checkpoint-postgres توفر الدالة setup() لإنشاء الجداول تلقائياً[reference:1].

import { PostgresSaver } from "@langchain/langgraph-checkpoint-postgres"; const DB_URI = process.env.SUPABASE_DB_URL; // رابط قاعدة البيانات const checkpointer = PostgresSaver.fromConnString(DB_URI); await checkpointer.setup(); // يجب استدعاؤها مرة واحدة عند أول استخدام

ملاحظة: في بيئة Vercel، يجب وضع SUPABASE_DB_URL في متغيرات البيئة (Environment Variables).

المرحلة 1: بناء الحالة (State) الأساسية

نحدد شكل البيانات التي ستنتقل بين العقد. نستخدم Annotation.Root مع reducer للرسائل (لتجميع سجل المحادثة) وبعض الحقول المخصصة[reference:2].

import { Annotation } from "@langchain/langgraph"; import { BaseMessage } from "@langchain/core/messages"; const AgentState = Annotation.Root({ // سجل المحادثة (يتم تجميعه تلقائياً) messages: Annotation({ reducer: (current, update) => current.concat(update), default: () => [], }), // السؤال الحالي question: Annotation, // الأجزاء المسترجعة من البحث retrievedChunks: Annotation, // الأجزاء بعد إعادة الترتيب rerankedChunks: Annotation, // الإجابة النهائية finalAnswer: Annotation, // عدد محاولات إعادة الصياغة (لتجنب الحلقات اللانهائية) retryCount: Annotation({ reducer: (_, update) => update, default: () => 0, }), // قرار التقييم (جيد / سيئ) grade: Annotation, });

المرحلة 2: بناء العقد الأساسية (Search, Rerank, Generate)

كل عقدة هي دالة تستقبل الحالة وتعيد تحديثاً جزئياً. نبدأ بالعقد التي تمثل المراحل الست السابقة.

// عقدة البحث (تستخدم Hybrid Search + GraphRAG) async function searchNode(state) { const { question } = state; // استدعاء دالة البحث التي بنيتها سابقاً (تجلب 20 جزءاً) const chunks = await hybridSearch(question); return { retrievedChunks: chunks }; } // عقدة إعادة الترتيب (Reranking) async function rerankNode(state) { const { question, retrievedChunks } = state; // استدعاء نموذج Reranker (مثل Cohere أو BGE) const topChunks = await rerank(question, retrievedChunks, 5); return { rerankedChunks: topChunks }; } // عقدة التوليد (Grounded Prompt) async function generateNode(state) { const { question, rerankedChunks, messages } = state; const context = rerankedChunks.join("\n\n"); const systemPrompt = `أنت مساعد طبي. أجب فقط من المقاطع التالية: ${context} إذا لم تجد الإجابة، قل: "المعلومة غير موجودة في الملفات المرفقة".`; const response = await llm.invoke([ { role: "system", content: systemPrompt }, ...messages, { role: "user", content: question } ]); return { finalAnswer: response.content, messages: [response] }; }

المرحلة 3: إضافة التقييم الذاتي (Agentic RAG)

هذه هي الخطوة التي تحول RAG العادي إلى RAG وكيلي. نضيف عقدة Grader تقيّم جودة الأجزاء، وعقدة Rewrite تعيد صياغة السؤال إذا كانت الجودة سيئة[reference:3].

// عقدة التقييم (Grader) async function gradeNode(state) { const { question, rerankedChunks } = state; const context = rerankedChunks.join("\n"); const gradePrompt = `هل الأجزاء التالية تجيب على السؤال: "${question}"؟ الأجزاء: ${context} أجب بـ "نعم" أو "لا" فقط.`; const grade = await llm.invoke(gradePrompt); return { grade: grade.content.trim() }; } // عقدة إعادة الصياغة (Rewrite) async function rewriteNode(state) { const { question, retryCount } = state; const rewritePrompt = `أعد صياغة السؤال التالي بطريقة تجعله أوضح وأكثر تحديداً للبحث: السؤال: ${question}`; const newQuestion = await llm.invoke(rewritePrompt); return { question: newQuestion.content.trim(), retryCount: retryCount + 1 }; }
مهم: يجب أن يكون هناك حد أقصى لعدد مرات إعادة الصياغة (مثلاً 2) لتجنب الحلقات اللانهائية. يمكن تنفيذ ذلك باستخدام حافة شرطية تتحقق من retryCount.

المرحلة 4: بناء الرسم البياني (StateGraph) وربط العقد

الآن نربط كل العقد معاً باستخدام StateGraph والحواف الشرطية.

import { StateGraph, START, END } from "@langchain/langgraph"; const workflow = new StateGraph(AgentState) // إضافة العقد .addNode("search", searchNode) .addNode("rerank", rerankNode) .addNode("grade", gradeNode) .addNode("rewrite", rewriteNode) .addNode("generate", generateNode) // المسار الافتراضي: من البداية إلى البحث .addEdge(START, "search") .addEdge("search", "rerank") .addEdge("rerank", "grade") // حافة شرطية بعد التقييم: إذا كانت الجودة جيدة، اذهب للتوليد .addConditionalEdges("grade", (state) => { if (state.grade === "نعم" || state.retryCount >= 2) { return "generate"; // جودة جيدة أو استنفدنا المحاولات } return "rewrite"; // جودة سيئة، أعد الصياغة }) .addEdge("rewrite", "search") // بعد إعادة الصياغة، ابحث مرة أخرى .addEdge("generate", END); // التوليد هو النهاية // تصريف الرسم البياني مع Checkpointer const graph = workflow.compile({ checkpointer });

لاحظ الحلقة: rewrite → search → rerank → grade. هذه الحلقة هي ما يسمح للـ AI بتصحيح مساره[reference:5].

المرحلة 5: إضافة الذاكرة الدائمة (Checkpointing)

عند تصريف الرسم البياني باستخدام { checkpointer }، سيتم حفظ الحالة بعد كل عقدة. لاستئناف محادثة، نمرر نفس thread_id[reference:6].

// تشغيل الرسم البياني const threadConfig = { configurable: { thread_id: "user-123-conv-456" } }; const result = await graph.invoke( { messages: [], question: "ما هي أدوية النسائية؟" }, threadConfig ); // لاحقاً: استئناف نفس المحادثة const continued = await graph.invoke( { messages: result.messages, question: "أعطني تفاصيل أكثر" }, threadConfig );

يمكنك أيضاً استخدام graph.getStateHistory(threadConfig) لعرض كل الحالات السابقة (Time Travel) واستكشاف مسارات بديلة[reference:7].

المرحلة 6: إضافة التدخل البشري (Human-in-the-Loop)

يمكننا إيقاف الرسم البياني عند عقدة معينة (مثلاً قبل حذف ملف أو تعديل بيانات) وطلب موافقة بشرية. نستخدم interruptBefore عند التصريف، أو دالة interrupt() داخل العقدة[reference:8][reference:9].

// عند التصريف: إيقاف قبل عقدة "deleteFile" const graph = workflow.compile({ checkpointer, interruptBefore: ["deleteFile"] // اسم العقدة الحساسة }); // في واجهة المستخدم: عرض طلب الموافقة // لاستئناف التنفيذ بعد الموافقة: import { Command } from "@langchain/langgraph"; await graph.invoke( new Command({ resume: { approved: true } }), threadConfig );

المرحلة 7: البث المباشر (Streaming) للتجربة التفاعلية

لتجربة مستخدم سلسة، يمكننا بث الأحداث (Tokens) والتحديثات (State) إلى الواجهة الأمامية باستخدام graph.stream()[reference:10].

// بث التحديثات (State) بعد كل عقدة for await (const event of await graph.stream(input, { ...threadConfig, streamMode: "updates", })) { console.log("تحديث:", event); // إرسال إلى الواجهة عبر SSE } // بث الرموز (Tokens) من LLM for await (const event of await graph.streamEvents(input, { ...threadConfig, version: "v3", })) { if (event.event === "on_chat_model_stream") { console.log(event.data.chunk.content); // بث الحروف } }

المرحلة 8: التوسع إلى وكلاء متعددين (Supervisor Pattern)

بعد إتقان الرسم البياني البسيط، يمكننا التوسع إلى نظام متعدد الوكلاء. مكتبة @langchain/langgraph-supervisor تسهل بناء مشرف يوجه الأسئلة إلى وكلاء متخصصين (وكيل الأدوية، وكيل الأمراض، وكيل الاختبارات)[reference:11].

import { createSupervisor } from "@langchain/langgraph-supervisor"; const supervisor = createSupervisor({ agents: [pharmacologyAgent, pathologyAgent, quizAgent], llm: supervisorLlm, // نموذج سريع للتصنيف }); const graph = supervisor.compile({ checkpointer });

هذا النمط يقلل التشتت ويزيد الدقة، لأن كل وكيل يتعامل فقط مع الأدوات والمعرفة الخاصة بتخصصه[reference:12].

05 ماذا يتغير بعد الانتقال إلى LangGraph؟

الجانبقبل (RAG خطي)بعد (LangGraph Agentic RAG)
التصحيح الذاتي لا يوجد. إذا فشل البحث، يهلوس الـ AI. حلقة تقييم وإعادة صياغة حتى الوصول إلى إجابة دقيقة.
الذاكرة تُفقد المحادثة عند إغلاق المتصفح. تُحفظ الحالة في Postgres وتُستأنف لاحقاً.
التخصص نموذج واحد لكل الأسئلة. وكلاء متخصصون (أدوية، أمراض، اختبارات) يقللون التشتت.
التدخل البشري غير ممكن. إيقاف التنفيذ عند نقاط حساسة وطلب موافقة.
المراقبة لا نعرف أين فشل البحث. كل عقدة تسجل حالتها. Time Travel لاستكشاف المسارات.

06 نصائح للتطوير بعد إتمام LangGraph

🚀 الرسم البياني الفرعي (Subgraphs)

يمكنك تغليف كل وكيل متخصص في رسم بياني فرعي (Subgraph) واستخدامه كعقدة في الرسم البياني الأب. هذا يعزز التماسك ويسمح بإعادة الاستخدام[reference:13].

🕰️ السفر عبر الزمن (Time Travel)

استخدم graph.getStateHistory() لعرض كل نقاط الحفظ، وتعديل الحالة يدوياً (updateState)، ثم استئناف التنفيذ من نقطة سابقة. هذا مفيد لتصحيح أخطاء الـ AI[reference:14].

📊 المراقبة (Observability)

دمج LangSmith أو OpenTelemetry لتتبع كل عقدة، عدد الرموز، والتكلفة. هذا ضروري للإنتاج[reference:15].

⚡ تحسين الأداء

استخدم نماذج أصغر للمهام البسيطة (مثل التقييم وإعادة الصياغة) لتقليل التكلفة. Groq مثالي للسرعة، بينما يمكن استخدام نماذج أكبر للتوليد النهائي.

07 الخلاصة

الانتقال إلى LangGraph ليس مجرد إضافة تقنية. إنه تحول من "نظام يجيب" إلى "نظام يفكر ويصحح نفسه". بعد إتمام المراحل الست، أصبحت المكونات جاهزة. الآن، مع LangGraph، ستتمكن من ربطها في تدفق ذكي، وإضافة الذاكرة، والتدخل البشري، والتوسع إلى وكلاء متعددين.

ابدأ بالمرحلة 0 (التأسيس) والمرحلة 1 (الحالة). ثم ابنِ عقدة البحث والتوليد. أضف التقييم لاحقاً. لا تحاول بناء كل شيء في يوم واحد. كل عقدة تضيف قيمة فورية.
