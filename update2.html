الدليل التنفيذي الشامل (Master Guide)

بناء نظام RAG متعدد الطبقات (Modular RAG) للقضاء على الهلوسة

Hybrid Search GraphRAG Reranking Grounded Prompt

🎯 لماذا نبني هذا النظام؟ (The Problem)

نظام RAG البسيط الذي نستخدمه حالياً يعتمد على البحث المتجهي (Vector Search) فقط. هذا النوع من البحث ممتاز في فهم "المعنى"، ولكنه يفشل بشكل كارثي في حالتين:

  • الأسماء الدقيقة: إذا سأل الطالب عن دواء "ميتفورمين"، قد لا يجد النظام الدواء إذا كان مكتوباً في جدول، لأن البحث المتجهي يبحث عن "الكلمة كمعنى" وليس "الكلمة كحروف".
  • الأسئلة الشاملة: إذا سأل الطالب "أعطني كل أدوية النسائية"، فالبحث المتجهي سيجلب 5 أجزاء فقط (وهي غير كافية)، وسيخترع الـ AI إجابة من معرفته العامة (الهرمونات).

الحل: بناء "فريق عمل" من 6 تقنيات تعمل معاً في خط أنابيب واحد (Pipeline) لتصفية وإثراء المعلومة قبل وصولها للـ AI.

1

المحطة الأولى: إجبار النموذج على "لا أعرف" (Grounded Prompt)

أسرع إصلاح وأهمه لمنع الهلوسة

Prompt Engineering Few-Shot

المشكلة: عندما لا يجد النظام إجابة في الملفات، يستخدم الـ AI معرفته العامة (الهرمونات)، ويقدم إجابة مضللة.

الحل التقني: تعديل الـ System Prompt ليكون صارماً جداً، مع استخدام تقنية "Few-Shot Prompting" (إعطاء النموذج أمثلة على كيفية الاعتذار).

نص الـ Prompt الجديد في chat.js:
أنت مساعد طبي. يجب عليك الإجابة **فقط** من المقاطع المرفقة. إذا لم تجد الإجابة في المقاطع، يجب أن ترد حرفياً بهذه الجملة: "المعلومة غير موجودة في الملفات المرفقة. يرجى مراجعة المصادر أو رفع ملف يحتوي على هذه المعلومة." ممنوع تماماً استخدام معرفتك العامة أو اختراع إجابة.

الأثر المتوقع: تقليل الهلوسة بنسبة 80%.

2

المحطة الثانية: التقطيع الهيكلي (Structural Chunking)

كيف نجعل الـ AI يفهم بنية الملف

Data Processing LangChain

المشكلة: في ملف upload.js الحالي، نقوم بتقطيع النص إلى 1000 حرف عشوائي. هذا يقطع جداول الأدوية إلى نصفين، ويخلط المواضيع ببعضها.

الحل التقني: استخدام مكتبات تقرأ العناوين (H1, H2, H3) وتقطع النص بناءً عليها. كل "جزء" يجب أن يحتوي على فكرة مكتملة (مثلاً: "دواء الميتفورمين" بكامل تفاصيله).

الخطوات العملية:
  • تثبيت مكتبة pdfplumber (Python) أو pdf-parse (Node.js) لاستخراج النص مع تنسيقه.
  • استخدام LangChain Text Splitters (تحديداً MarkdownHeaderTextSplitter).
  • إضافة Metadata لكل جزء (نوع المحتوى: دواء / مرض / عرض / تحليل).
3

المحطة الثالثة: البحث الهجين (Hybrid Search + BM25)

البحث الحرفي + البحث الذكي

Supabase BM25 pg_trgm

المشكلة: البحث المتجهي يبحث عن "المعنى" فقط، ولا يجد الأسماء الدقيقة (أسماء الأدوية، المصطلحات اللاتينية).

الحل التقني: دمج البحث المتجهي (pgvector) مع البحث النصي التقليدي (BM25).

كيف تطبقها في Supabase؟
-- 1. تفعيل البحث النصي CREATE EXTENSION IF NOT EXISTS pg_trgm; CREATE EXTENSION IF NOT EXISTS unaccent; -- 2. إضافة عمود للبحث النصي ALTER TABLE document_chunks ADD COLUMN textsearch tsvector GENERATED ALWAYS AS (to_tsvector('arabic', content)) STORED; -- 3. إنشاء فهرس (Index) للبحث السريع CREATE INDEX idx_chunks_textsearch ON document_chunks USING GIN(textsearch);

ثم في دالة search.js، نقوم بدمج نتائج البحث النصي (باستخدام websearch_to_tsquery) مع نتائج البحث المتجهي (pgvector).

4

المحطة الرابعة: إعادة الترتيب (Reranking)

تصفية النتائج لاختيار الأفضل فقط

Cohere Hugging Face BGE

المشكلة: البحث الهجين قد يجلب 50 جزءاً، بعضها جيد وبعضها سيئ. إرسال 50 جزءاً للـ AI يشتته ويزيد التكلفة.

الحل التقني: استخدام نموذج Cross-Encoder يعيد ترتيب الأجزاء ويختار أفضل 5 فقط.

الأدوات المجانية:
  • Hugging Face Inference API: نموذج BAAI/bge-reranker-base.
  • Cohere Rerank: يوفر حصة مجانية شهرية (1000 طلب/شهر).

الأثر المتوقع: زيادة دقة الإجابة بنسبة 30-40%.

5

المحطة الخامسة: الرسم البياني المعرفي (GraphRAG)

الميزة القاتلة للأسئلة المعقدة

Neo4j LLMGraphTransformer Cypher

المشكلة: إذا سأل الطالب "ما هي الأدوية التي تعالج الصداع النصفي وتسبب النعاس؟"، البحث العادي لن يجد الإجابة لأن المعلومة متفرقة في ملفات مختلفة.

الحل التقني: بناء قاعدة بيانات علائقية (Neo4j) تربط (الدواء) بـ (المرض) بـ (العرض).

ملاحظة هامة: هذه المحطة هي الأكثر تعقيداً وتكلفة. لا تبدأ بها إلا بعد إتقان المحطات 1-4. تتطلب تشغيل خادم Neo4j وتعلم لغة Cypher.
6

المحطة السادسة: التوجيه الذكي (Query Routing)

الشرطي الذي يوجه السؤال للمسار الصحيح

Intent Classification Groq

المشكلة: إرسال كل سؤال إلى كل قواعد البيانات يبطئ النظام ويجلب معلومات غير ذات صلة.

الحل التقني: استخدام نموذج صغير وسريع (مثل Llama 3.1 8B) لتصنيف نية الطالب قبل البحث.

خطوات التنفيذ:
  • عند وصول السؤال، يمرر إلى نموذج التصنيف مع Prompt: "صنف هذا السؤال إلى: (دواء، مرض، فسيولوجيا، تحليل، عام)".
  • إذا كان النوع "دواء"، يتم البحث فقط في جدول الأدوية (في Neo4j أو في Metadata المحددة).
  • هذا يقلل زمن البحث ويحسن دقة النتائج.

🗓️ خطة التنفيذ الزمنية (4 أسابيع)

الأسبوع 1

التأسيس السريع

تطبيق Grounded Prompt (المحطة 1) + التقطيع الهيكلي (المحطة 2) + البحث الهجين (المحطة 3). ستشعر بفرق فوري في دقة الإجابات.

الأسبوع 2

التصفية الذكية

تطبيق Reranking (المحطة 4) و Query Routing (المحطة 6). ستلاحظ سرعة استجابة أعلى وإجابات أكثر تركيزاً.

الأسبوع 3

الميزة القاتلة

بناء GraphRAG (المحطة 5). هذا الأسبوع سيكون الأصعب، ولكنه سيمكنك من الإجابة على أسئلة معقدة لم يستطع أحد الإجابة عليها.

الأسبوع 4

التقييم والاختبار

اختبار النظام بالكامل مع الطلاب الـ 10. استخدام أداة RAGAS لقياس الدقة ومقارنة النتائج قبل وبعد.
